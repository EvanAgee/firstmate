=== CLAIM 1: an unkeyed line lands under the shared key 'default',
===          so a SECOND unkeyed decision silently overwrites the first.
--- two UNKEYED questions (what the old scaffold's example produced)
    worker's status file:
      needs-decision: do we drop the legacy column or keep it
      needs-decision: should the export be CSV or JSON
    firstmate sees as OPEN DECISIONS:
      default	needs-decision	should the export be CSV or JSON

--- same two questions KEYED (what the new scaffold's example produces)
    worker's status file:
      needs-decision [key=legacy-column]: do we drop the legacy column or keep it
      needs-decision [key=export-format]: should the export be CSV or JSON
    firstmate sees as OPEN DECISIONS:
      legacy-column	needs-decision	do we drop the legacy column or keep it
      export-format	needs-decision	should the export be CSV or JSON
